# PANDORA: аудит 02.11.2026

## Границы результата

Исходный приложенный ZIP совпал с исходниками checkout `bdbf544`.
Рабочий режим этого результата — **Pandora Win, PAPER ONLY, 500 USDT**:
`PANDORA_FLOW_V2=0`, `PANDORA_PUMP_V3=0`. Экспериментальные Flow V2 / Pump V3
сохранены для совместимости; их иная стратегия и стартовый капитал не являются
режимом, рекомендованным этим аудитом. При переключении экспериментальных режимов
существуют старые процедуры инициализации/архивации: не включать их на действующем
счёте. Аудит не выполнял reset рабочей базы.

## Подтверждённые дефекты и изменения

1. Discovery не применял минимум 10 млн USDT в основном режиме. Теперь допускаются
   только рынки из метаданных Trading USDT LinearPerpetual с оборотом >=10 млн,
   spread <=0.20%, свежими bid/ask и объёмом верхнего уровня >=1000 USDT с каждой
   стороны. Это проверка верхнего уровня, а не полноценная модель глубины стакана.
   Вход и ADD повторно проверяют живые котировки; блокировка не закрывает позицию.
2. Четырёхчасовая фиксация состава не разрешала досрочную замену. Теперь ranking
   обновляется каждую секунду, плановый период сохраняется в PostgreSQL, а после
   180 секунд непрерывно наблюдаемого затухания заменяется один член группы на
   готового кандидата. Причины и время ротации сохраняются. Stale/outage не доказывает
   затухание. При отсутствии готовой замены позиция сохраняет сопровождение.
3. Старые тесты ожидали мгновенную ротацию вопреки уже существующему четырёхчасовому
   периоду. Исходный набор: 227 тестов, 6 failures, 0 errors/skips. Эти ожидания
   заменены проверками текущего контракта; независимые проверки свежести сохранены.
4. Структурное подтверждение failed retest могло исчезнуть до окончания 3 секунд
   встречного контроля. Оно теперь сохраняется внутри непрерывной свежей встречной
   последовательности. Собственный контроль, новый благоприятный экстремум,
   неизвестный поток или разрыв данных снимают подтверждение.
5. Watch мог сохранять старое подтверждение re-entry после нового встречного
   импульса. Оно сбрасывается встречным контролем и stale; нужен новый подтверждённый
   импульс. Существующие атомарные claims исключают повтор одного события.
6. Восстановление более нового persisted H1/M15 anchor могло вернуть разрешение
   входа после пробоя опорного уровня. Текущая закрытая H1/M15 история и stale
   повторно блокируют вход; идентичность последнего локала остаётся видимой.
   В API отдельно доступны последние подтверждённые H1 High и Low.
7. ADD запрещён при быстром встречном контроле и начатом подтверждении выхода,
   даже если минутный sustained context ещё указывает старое направление.
8. Net PAPER PnL новых позиций учитывает fee и явную модель проскальзывания
   `PANDORA_SLIPPAGE_FRACTION` (по умолчанию 0.0005 на каждую сторону). Параметр
   фиксируется в features на входе. Старые позиции без него сохраняют прежний
   учёт. Mark, close, equity, maintenance и MFE используют общий расчёт.
   Средняя цена после ADD остаётся quantity-weighted; модельные издержки
   аддитивны по legs. Это оценка затрат, не эмуляция реальных fills/funding.
9. Сохраняются общий MFE/MAE, MFE в % маржи и отдельные segment MFE до/после ADD.
   Смена средней цены не стирает прежний максимум. Фиксированного MFE-stop нет.
10. Основной мобильный монитор показывает один вертикальный экран без кнопок,
    вкладок и таблиц. Есть Mark, исторический H1, активный H1/M15, причины WAIT/HOLD,
    поля позиции, MFE, время, uptime, статус данных и история доливок. Состояние
    LIVE больше не объявляется безусловно. Обновление каждые 5 секунд сохраняет
    позицию прокрутки. Полная история доступна также через cursor API.

## ETH: LONG структура при SHORT позиции

Само различие надписей не доказывает ошибку: H1 anchor, более новый подтверждённый
M15 execution local и открытая позиция — разные сущности. Закрытие требует свежего
встречного executed control минимум 3 секунды вместе с новым противоположным
локалом либо подтверждённым структурным пробоем/failed retest. При отсутствии
этих доказательств позиция остаётся открытой с причиной HOLD/WAIT, а не закрывается
ради совпадения надписей. Конкретная рабочая ETH-сделка не воспроизведена без
живых временных рядов и состояния рабочей БД; синтетическая зеркальная регрессия
M15 Low против старого H1 High проверяется в test_incident_locals.

## Запуск и архитектура

```bash
bash scripts/cloud_dev.sh install
bash scripts/cloud_dev.sh test /workspace/.pandora-cloud/release-result.json
bash scripts/cloud_dev.sh app
```

Сценарий для данной облачной машины создаёт отдельные `pandora_dev` и
`pandora_test` на PostgreSQL 17, bind mount вне репозитория; порт только loopback.
Trust-auth предназначен исключительно для изолированной разработки. Docker,
Python 3.12 и rg должны быть доступны. Производственная конфигурация по-прежнему
задаётся через DATABASE_URL, см. README_PANDORA_WIN.md; облачный helper всегда
выбирает локальную БД, не использует переданный production URL.

Поток: public ticker/metadata → scanner cohort/candidates → H1/M15 bootstrap →
RollingMarketData executed tape → локалы/pressure state → runtime/risk → fenced
PostgreSQL ledger → read-only HTTP monitor/API. Held-позиции подписаны и
обслуживаются независимо от членства в Discovery. На старте кандидаты сразу
получают подписки; выбор выполняется после реально наблюдаемого прогрева, не
раньше наличия данных и не после искусственного ожидания четырёх часов.

## Проверки и ограничения

Актуальный полный результат: `validation/release-result.json`, лог
`validation/release.log`. Runner записывает время и SHA-256 всех Python-файлов;
packager проверяет соответствие отчёта архивируемому коду.
`validation/mobile-layout.json` — Chromium с эмуляцией 320/360/412 px:
HTML реального HTTP-ответа и отдельный синтетический layout fixture отображены
офлайн через DevTools. Проверены ширина и отсутствие кнопок/переполнения.
Синтетические сделки не добавлялись в приложение или рабочую историю.
Физический Samsung и сетевое обновление браузера на нём не проверялись.

На отдельной локальной БД проверены /api/pandora, / и /health (200),
/health/risk (503 при недоступном рынке), PAPER-счёт 500 и отсутствие сделок.
Перезапуск не обнуляет счёт. Тесты используют реальную PostgreSQL и локальный
WebSocket с синтетическими Bybit-сообщениями; это не бэктест доходности.

Bybit CONNECT блокируется текущей политикой прокси (403). В черновике среды
добавлены api.bybit.com и stream.bybit.com. До применения настроек и успешной
повторной REST/WSS проверки живое поведение **не подтверждено**. Render API/секреты
не предоставлены; deploy и LIVE на Render не подтверждены. Производственная
история не читалась и не изменялась. Обещаний сохранения максимального MFE,
доходности или отсутствия ликвидаций нет.
