# Cortex audit and implemented research layer

Audited 2026-11-07. Research only; real orders remain disabled. **MONITOR UNCHANGED: YES.**

## Finding and decision

The archive does not demonstrate a functioning or useful 20B Cortex. Its boot log identifies llama.cpp build b12110 and `ggml-org/gpt-oss-20b-GGUF:MXFP4`; `/health` became ready at attempt 24. The archived daemon report records **0 successful calls and 18 HTTP 400 errors**. Health readiness establishes a server response, not successful structured generation. The response bodies, per-call timings, memory profile, model weights and paired Quantum/Cortex predictions were not included. The cause of these particular HTTP 400 responses therefore cannot be identified conclusively.

The operational replacement is a numerical statistical analyst in a separate process. The LLM is optional and disabled by default. Numerical inference and model learning never wait for Cortex, and Cortex has no reference to a model object or checkpoint promotion function. This is a reliability and evidence-control improvement. An improvement in Local detection quality from Cortex has **not** been demonstrated.

## Original implementation

`hype_local_only/cortex_daemon.py` previously sent a summary of archived associations and current status to a Chat Completions endpoint with a 180-second request timeout. It retried HTTP 400 using unconstrained generation, extracted text between the first and last braces, did not validate the decision fields, and could accept `reasoning_content` as its answer. It had no reproducibility trial, calibrated meta-probability, numerical hypothesis test, or paired held-out comparison. The relationship-memory summaries omitted the underlying time series: access to a 30-day summary is not analysis of every observation in 30 days.

The archived micro relationship baselines/example counts include final historical OOS rows; H1 relationships were calculated from all historical examples. These are descriptive, retrospectively selected associations. They cannot establish held-out Cortex improvement. In addition, the original historical feature generator used incomplete bars. The new study uses only the rebuilt causal dataset generated by Quantum; it does not reuse contaminated archive features as clean evidence.

The older `hype_quant/astra_cortex.py` is a separate, synchronous, three-strategy paper controller. Its `observe()` can synchronously invoke a long request and retry; its normalized confidence and directional episode scores do not establish Local detection quality. It is not used by the Local-only daemon and has not been represented as fixed, trained, or promoted by this work. Local-only startup and the new adapter supersede the relevant execution path.

## Implemented components

* `cortex_provider.py`: explicit `disabled`, `local_llama`, and `openai` backends. Local URLs must use loopback. OpenAI requires both `OPENAI_API_KEY` and an explicit `CORTEX_API_MODEL`; no model name or paid connection is invented. Configuration readiness and successful response verification are separate metadata.
* Local requests use the JSON-schema envelope documented by llama.cpp. Only an explicit unsupported-schema HTTP 400 permits one JSON-object compatibility request. Arbitrary HTTP 400, missing final content, truncation, refusals, markdown, embedded objects, unknown fields, invalid enums, NaN/infinity, and invalid hypothesis features are rejected. The full final answer is validated locally even when a server promises schema enforcement. Reasoning text is not salvaged.
* Prompt and response sizes are bounded to 64 KiB and 256 KiB respectively; generation has a configured 1–30 second budget, bounded socket waits and no arbitrary retry loop. A single daemon background worker has a queue of size one. The daemon continues to emit numerical status while that worker waits, and daemon threads do not prevent process exit. A pathological remote transport can exceed a precise wall deadline by a bounded socket wait; this does not block Quantum.
* `cortex_meta.py`: train-only median/effect conditions and limited feature pairs; chronological maturity purge and embargo; hourly event aggregation; explicit missingness; multiplicity-adjusted validation intervals; checksum-verified persistent numerical memory. Target/evaluation feature names and contract IDs 83–110 are excluded.
* `cortex_research.py`: persists accepted research associations, rejected hypotheses and insufficient evidence. It reserves the final OOS entirely. Optional LLM proposal validation requires a separate forward dataset beyond the historical dataset and prediction times after proposal creation; historical labels from before a live hypothesis cannot retrospectively validate it. These records never authorize model promotion.
* `cortex_daemon.py`: reads fresh producer evidence, records at most 256 distinct observations, compares probabilities only within the same candidate and stage, describes feature-distribution shifts using 32 prior/16 recent distinct snapshots, and persists LLM proposals as pending validation. Repeated polls do not create independent evidence. Distribution shifts are diagnostics, not a validated market-regime classifier. Stale status/evidence produces an explicit WAIT advisory. Statistical confidence remains 0 because no calibrated meta-classifier exists.
* State/status writes use a unique temporary file, fsync and atomic replacement. A process lock prevents simultaneous Cortex writers for one directory. Corrupt research/state memory is ignored with an explicit diagnostic. Invalid LLM configuration falls back to the numerical analyst.
* `hype_quant/start_local_cortex.sh` no longer deletes unrelated software or caches, runs sudo, pipes downloads into a shell, or automatically installs a launcher. It requires an existing binary and an explicit readable local model, or explicit opt-in `CORTEX_HF_MODEL`. Startup/health checking is bounded. Failure cleanup terminates only the child it started; an archived PID is never a kill instruction.

## Actual numerical experiment

Input: `artifacts/quantum_research/causal_candidates.jsonl.gz`, with completed-bar causal features, finalized alternating H1 teacher labels and `label_mature_ms`. Its SHA-256 is recorded in the numerical memory/report. The source still has an explicit historical receipt-time assumption: bar/source availability is reconstructed; real feed latency cannot be recovered.

The study discovers conditions before 2026-10-23, excluding labels that had not matured before the split. Validation starts after a three-hour embargo and ends before 2026-10-27, also excluding unmatured labels. Final OOS rows on/after 2026-10-27 are counted and reserved without accessing their feature/label values in the discovery loop. These association-study folds are stated separately from Quantum's calibration/model-selection folds; their metrics must not be compared as equivalent classifier evaluations.

| Outcome | Count |
| --- | ---: |
| Discovery rows | 1,543 |
| Validation rows | 278 |
| Final OOS rows reserved | 490 |
| Train-derived single/pair hypotheses | 72 |
| Insufficient independent event support | 56 |
| Rejected by validation criterion | 16 |
| Validated research associations | 0 |
| Production promotions | 0 |

Full conditions, support, rates, intervals and rejection states are in `artifacts/cortex_research/CORTEX_HYPOTHESIS_REPORT.json`. The checksummed `CORTEX_RESEARCH_MEMORY.json` can be passed to the daemon. This result does not establish that every possible nonlinear/temporal relationship is absent. It shows that these 72 selected hypotheses lack the required evidence in this validation window. No LLM hypothesis is called validated because of a persuasive explanation.

Each side/hour at one stage contributes at most one unit: any matching snapshot may flag that hourly event, and its teacher outcome is the existence of a strict local of that side in the hour. This is an association test, not a replacement Local label or a measurement of exact detection delay. Bonferroni-adjusted Wilson intervals control multiplicity only under their independence assumptions; adjacent market hours and horizons remain dependent. A blocked forward replication and paired model predictions are still necessary. The stored `incremental_quantum_cortex_oos_gain` is null.

## Verified model alternatives and limits

Official source snapshots are included in `docs/official_sources/`. Retrieval on 2026-11-07 verifies documentation, not a successful model download, API account access, or superiority on HYPE.

| Candidate | Verified characteristics | Suitability and actual test status |
| --- | --- | --- |
| Statistical Cortex | Implemented, bounded, no LLM/GPU dependency | Chosen operational layer; association experiment above; no incremental detection gain established |
| OpenAI gpt-oss-20b | Official README: 21B total / 3.6B active parameters, Apache 2.0, MXFP4 model fits within 16 GB memory; Harmony formatting required | Existing archive choice is legitimate. CPU latency, memory at the configured context, repeatability and JSON success rate are unmeasured here; no weights/service running here |
| Qwen3 / Qwen3-2507 | Official repository: dense 0.6/1.7/4/8/14/32B and MoE 30B-A3B/235B-A22B; Apache 2.0; thinking and non-thinking variants/modes; llama.cpp serving examples | Smaller 4B/8B non-thinking variants are feasible candidates for a later local structured-output trial. No installation, latency result or Local-quality advantage claimed |
| Chronos-2 | Official repository: 120M model and 28M small variant; Apache 2.0; univariate/multivariate/covariate forecasting | More appropriate for a numerical forecasting challenger than an explanation layer. Forecast accuracy on other datasets does not prove LOW/HIGH classification. No weights benchmarked here; unknown future covariates must not be supplied |
| TimesFM 3.0 / 2.5 | Current official README: 3.0 supports multivariate/covariate forecasting; downloaded 3.0 weights have a non-commercial/non-production license. Source and weights through 2.5 remain Apache 2.0; 2.5 is 200M parameters | Potential forecasting challenger with separate label/calibration work. A self-hosted commercial deployment cannot assume the 3.0 weight license equals the code license. Authorized Google Cloud use is documented separately. Not installed/tested |
| Cloud reasoning API | Explicit OpenAI Responses adapter with strict structured output implemented and mocked | No configured secret, verified model account availability, provider latency, current paid price, or measured HYPE advantage. API pricing page was unreachable in this environment; cost remains unverified |

No GPU device or `nvidia-smi` was available in this environment. Downloading a large LLM merely to claim it is installed would not validate its incremental utility. Source-reported memory sizes are not measurements on this machine, and no zero-cost claim is made for CPU operation or hosted services. This is a verified candidate comparison, not an assertion that these are the universally best models available.

## Reproduction and measurement

From the project root, with the project's installed dependencies:

```bash
PYTHONPATH=src python -m unittest discover -s tests -p 'test_cortex*.py' -v
PYTHONPATH=src python -m research.hype_local_only.cortex_research \
  --snapshots artifacts/quantum_research/causal_candidates.jsonl.gz --causal-data \
  --memory-out artifacts/cortex_research/CORTEX_RESEARCH_MEMORY.json \
  --report-out artifacts/cortex_research/CORTEX_HYPOTHESIS_REPORT.json
CORTEX_BACKEND=disabled PYTHONPATH=src python -m research.hype_local_only.cortex_daemon \
  --checkpoint-dir runtime --minutes 30 \
  --research-memory artifacts/cortex_research/CORTEX_RESEARCH_MEMORY.json
```

The producer separately writes fresh `LOCAL_ONLY_STATUS.json` in the same runtime directory; the daemon does not consume an archival checkpoint directory as live evidence. To opt into a local model, first start a separately installed model server and set `CORTEX_BACKEND=local_llama`, `CORTEX_LOCAL_URL`, and `ASTRA_CORTEX_MODEL`. To opt into OpenAI, configure the key outside logs/chat and explicitly set `CORTEX_BACKEND=openai` and `CORTEX_API_MODEL`. A configured adapter remains unverified until it returns a valid response.

**40 Cortex offline tests passed** after the initial implementation, including future/OOS invariance, maturity purge, event deduplication, mismatched/future/stale evidence, missing data, corrupt memory, bounded worker behavior, proposal timing, single writer, strict provider validation, schema negotiation and safe startup. `bash -n` passed for the launcher. A disabled-provider daemon smoke test exited successfully with WAITING_FOR_FRESH_QUANTUM and `connection_verified=false`; no remote request was made.

`artifacts/cortex_research/SMOKE_BENCHMARK.json` contains 150 synthetic numerical-analysis timings including atomic persistence with Python allocation tracing enabled: p50 3.00 ms, p95 4.93 ms, p99 5.10 ms, peak traced allocations 159,755 bytes. These are a small synthetic CPU timing sample, not live p99, total RSS, a 20B inference measurement or a quality benchmark. Complete forward paired evidence, real JSON success/repeatability trials and provider cost/latency measurement remain outstanding.
