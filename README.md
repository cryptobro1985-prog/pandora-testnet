# PANDORA PAPER — H1 + executed trades

Только PAPER. Реальных ордеров нет. LIVE и доходность не подтверждены.

## Логика

H1 задаёт разрешённое направление по закрытым свечам. Исполненные сделки Bybit Public Trades и реакция цены определяют контроль. M1/M3/M5/M15 не задают момент исполнения. Pandora Win выбирает до пяти актуальных PUMP-токенов сканером Bybit; открытые позиции и ожидания перезахода продолжают получать данные после ротации. Незакрытая H1-свеча не меняет подтверждённое направление. Отдельные PAPER-счета 1.1/1.3/1.4 показаны для сравнения; их результаты не суммируются с основным счётом.

Первый встречный импульс переводит открытую позицию в WEAKENING_OBSERVE. Новое благоприятное экстремальное значение поглощает отскок; его размер сохраняется как наблюдавшийся шум. Выход требует встречного контроля и движения больше наблюдавшегося шума, которое пробивает границу предыдущего поглощённого отскока либо следует за неудачным возвратом к экстремуму. При отсутствии предшествующей структуры требуется неудачный ретест. Поэтому мгновенная V-образная смена без ретеста может дать поздний выход. Это проверяемая причинная гипотеза, а не доказанный оптимальный алгоритм.

Caterpillar сохраняет H1-направление и ждёт подтверждённого завершения встречного движения по зеркальной структуре. Число повторов не ограничено. MFE/MAE — статистика, фиксированных TP и MFE-стопа нет. Максимально возможную прибыль алгоритм гарантировать не может.

Два последних торгованных ценовых уровня используются для наблюдения давления. Качество этого наблюдения на реальном рынке ещё нужно измерить. Пределы свежести и транспортные таймауты технические, не откалиброваны по живой Bybit в этой среде.

## Деньги и история

Новая пустая PAPER-база начинает с $500. На существующей базе стартовый INSERT использует ON CONFLICT DO NOTHING: баланс не сбрасывается. Маржа — 20% текущего торгового equity, ограничена свободной маржой с резервом моделируемых комиссий; плечо до 25x и контрактного максимума. Одна позиция на токен; при недостатке маржи вход блокируется. Комиссия модели 0.045% с каждой стороны; реальное проскальзывание и funding не смоделированы.

Сохраняются канонические таблицы local_v12_* и local_h1_direction. Старые таблицы сделок читаются только для архивной истории. Не меняйте DATABASE_URL при обновлении; ZIP не содержит копию Neon. Не запускайте второй движок на той же базе. Инициализация всех PAPER-счетов сохраняет существующий баланс и историю; автоматические сбросы при запуске удалены. Lease защищает записи одного владельца. Перед заменой работающей версии сохраните штатный snapshot базы.

## Запуск

Python 3.12. `pip install -r requirements.txt`, затем `python app.py`. Требуется DATABASE_URL существующей PostgreSQL, необязательны PORT (10000), RENDER_GIT_COMMIT, PANDORA_CONTROL_TOKEN для ручного PAPER-закрытия. Публичные Bybit данные не требуют API-ключа. Монитор `/`, JSON `/api/dashboard`, история `/api/strategy1/history`, готовность `/health` (маршруты уточняйте в app.py). Render использует существующий сервис, Dockerfile и тот же DATABASE_URL. В ZIP нет ключей и конфигурации аккаунта Render.

## Проверки

`pip install -r requirements-dev.txt`. Укажите DATABASE_URL из отдельной тестовой базы и PANDORA_TEST_DATABASE_URL_FILE — путь к файлу с тем же URL. `python scripts/run_release_tests.py --report validation/release-result.json`. Runner завершается ошибкой при пропущенных интеграционных тестах. Не указывайте production Neon для тестов.

WebSocket-интеграция использует настоящий локальный сокет с синтетическими кадрами Bybit и PostgreSQL. Эти результаты не являются рыночным PnL. Реальное подключение Bybit в облачной среде отклонено прокси: CONNECT 403, см. validation/live-websocket-probe.json. Деплой Render, heartbeat и 12-часовой рынок не проверены.

## Проверено 2026-11-01

Полный актуальный результат проверок — в `validation/release-result.json`: тесты без ошибок и пропусков, включая свежую PostgreSQL, повторную инициализацию четырёх счетов без потери истории, WebSocket-цикл открытия/закрытия/перезахода пяти выбранных рынков и ротацию 13 рынков для проверки маржи. GitHub Actions запускает тот же runner на Python 3.12 и отдельной PostgreSQL 17.

Локальный запуск с пустой базой и HTTP-запросы к `/health`, `/api/dashboard`, `/api/strategy1/history`, `/` проверены. HTTP health не доказывает готовность рынка: `/health/risk` требует свежих данных и подтверждённого H1. Render и реальный Bybit отдельно не подтверждены; CONNECT к ним отклонён прокси среды.
